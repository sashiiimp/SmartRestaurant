# SmartRestaurant: ML evaluation (actual results)

These numbers were produced by `flask smartrest train` on the synthetic dataset (750 days x 10 items, seed 42,
generated by `app/seed/generate.py`). Nothing here is planned or estimated: it is copied from the stored
`model_versions.metrics` of the trained model `v20260921-1`. Re-running the same command on the same data
reproduces them (fixed seeds, pinned library versions).

**Read this first.** The data is synthetic. Its effects (weekday pattern, Poya days, promotions, rain, trend) were
written by us, so the model is being asked to recover structure we put there. The results show that the pipeline
works and that a model with contextual features beats a same-weekday-last-week rule *when such structure exists*.
They do not show how accurate the system would be in a real restaurant.

## Set-up

| Item | Value |
|---|---|
| Target | quantity sold per menu item per day |
| Hold-out | last 56 days (2026-07-27 to 2026-09-20), chronological, never used for fitting; 560 item-days |
| Training rows | 6,660 (2024-09-29 to 2026-07-26; each item's first 28 days are dropped for lag features) |
| Features | weekday, weekend, month, public holiday, Poya day, school holiday, promotion discount, rain, temperature, lags 7/14/21/28, rolling means, item |
| Weather in the hold-out | seasonal estimate computed from the training period (what the model sees when forecasting tomorrow) |
| Models | naive (same weekday last week), seasonal mean of the last 4 same weekdays, Random Forest (300 trees), XGBoost (300 trees, depth 5) |
| Selection | lowest hold-out MAE; the shipped model is then refit on all history |

## Results on the hold-out

| Model | MAE | RMSE | MAPE % | WAPE % | R2 | Bias |
|---|---|---|---|---|---|---|
| naive_lag7 (baseline) | 12.87 | 17.68 | 22.8 | 19.9 | 0.824 | 0.16 |
| seasonal_mean4 | 11.01 | 14.86 | 19.6 | 17.1 | 0.876 | -0.18 |
| random_forest | 9.81 | 13.33 | 17.4 | 15.2 | 0.900 | 0.01 |
| **xgboost (selected)** | **9.45** | **12.76** | **16.7** | **14.6** | **0.908** | 0.14 |

- XGBoost beat the naive baseline on MAE by 26.6% (9.45 vs 12.87), so the acceptance criterion S1 is met, and beat
  Random Forest by a small margin (9.45 vs 9.81; the two are close and this gap should not be over-interpreted).
- **Noise floor.** The generator's noise-free expected demand has an MAE of 8.28 against the sampled sales. No model
  can do better than that on this data. XGBoost is within 1.17 portions of it.
- Overall WAPE 14.6% meets the planned target of about 15% (a target, not a promise; it depends on the generator's
  noise level).
- Bias is close to zero for all learned models, so the forecast does not systematically over- or under-prepare.
- MAPE excludes no rows (no actual of zero in the hold-out).

### Live monitoring check

Admin > Monitoring > Forecast accuracy compares stored forecasts with actual sales. For the 56 backfilled days it
reports MAE 9.46, WAPE 14.7%, bias -0.05 over 560 item-days, matching the hold-out, as expected: the backfill uses the
copy of the model fitted before those days (`eval_model` in the artifact), so it is out-of-sample. (An earlier
version used the refit model and showed a flattering MAE of 7.9; that was in-sample and was corrected.)

### What the model relies on

Tree importance (XGBoost): which menu item 94%, 7-day rolling mean 1.6%, lag 7 1.1%, lag 14 0.6%, weekday 0.5%.
The item identity dominates because items differ ten-fold in volume, so this figure says little about the value of
the contextual features. The proposal's question about contextual factors needs an ablation (calendar + lags, then
+ holiday, + promotion, + weather). That was planned as a stretch item and **has not been done**.

## Limitations to state in the report

1. Synthetic data: accuracy is not evidence about real restaurants; real data can replace it through the same CSV import.
2. Sales are not censored by stock-outs in the generator; real sales understate demand when an item sells out.
3. One hold-out window, no cross-validation, no hyperparameter search; differences of a few percent between
   Random Forest and XGBoost are within what another split could change.
4. No prediction intervals: the safety buffer is a fixed percentage, not derived from forecast uncertainty.
5. Weather is a seasonal average at forecast time; no weather API.
6. The hold-out MAE belongs to the train-only fit; the shipped model was refit on all history (8 more weeks).
7. The Poya-day and other holiday dates were computed (full-moon calculation) or entered from memory; verify
   `data/holidays_lk.csv` against the official calendar before quoting them.
